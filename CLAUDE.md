## Architecture

The app follows a layered BLoC + Repository pattern:

```
Presentation (lib/src/)
    └── Application/State (lib/data/app_bloc/)
            └── Data (lib/data/database/ + lib/data/app_bloc/auth_repository/)
```

### Entry & Bootstrap (`lib/main.dart`)

1. Firebase is initialized via `firebase_options.dart` (generated by FlutterFire CLI)
2. `AuthRepository` is created and injected at the root
3. `FirebaseManager.init()` sets up the Firestore singleton
4. `App` widget wraps everything in `RepositoryProvider<AuthRepository>` → `BlocProvider<AuthenticationBloc>` → `MultiBlocProvider` (LanguageBloc, StyleCubit) → `MaterialApp.router`

### Navigation (`lib/routes.dart`)

GoRouter with auth-reactive redirection via `GoRouterRefreshStream(authBloc.stream)`:
- Unauthenticated → `/login`
- Authenticated → `/home` (ShellRoute wrapped by `NavigationHomeScreen`)
- All feature routes (`/text-editor`, `/task-editor`, `/archived`, `/settings`, etc.) are nested under the shell

### State Management (`lib/data/app_bloc/`)

| Bloc/Cubit | Responsibility |
|---|---|
| `AuthenticationBloc` | Listens to `AuthRepository.user` stream; drives route redirects |
| `LoginCubit` | Form state for email/password login |
| `SignUpCubit` | Form state for registration |
| `LanguageBloc` | App locale (persisted via `HydratedBloc`) |
| `StyleCubit` | Theme preferences (persisted via `HydratedBloc`) |

### Authentication (`lib/data/app_bloc/auth_repository/`)

`AuthRepository` wraps Firebase Auth: email/password signup/login, Google Sign-In, user stream. The `User` model (not `firebase_auth.User`) is defined in `user.dart` with app-specific fields (isAnonymous, isBlocked, isDataCloud, verifiedAccount, etc.).

### Data Layer (`lib/data/database/`)

- **`FirebaseManager`**: Singleton for Firestore CRUD. User-scoped collections at `K_NOTE/general_data/USERS/{userId}/notes` and `.../tasks`. Optional encryption keys stored at `.../keys/master_key`.
- **`DatabaseManager`**: Hive-based local persistence for settings and preferences. ObjectBox code exists but is commented out (legacy).
- **`NoteModel`**: Has `savingModeValue` (cloud/local/cloudAndLocal), `isLocked` (encryption), `isDeleted`, `isArchived`. Serialized via `fromMap`/`asMap`.

### UI (`lib/src/`)

- `pages/` — feature screens (HomeScreen, TextEditor using flutter_quill, TaskEditor, ArchivedScreen, TrashCan, SettingPage, etc.)
- `login/` — auth screens and forms
- `widgets/` — reusable components (NoteCard, progress button, etc.)
- `custom_drawer/` — app drawer with user controller

### Testing (`test/unit/`)

Tests mirror the `lib/data/` structure. Uses `bloc_test` for BLoC state transition testing and `mocktail` for mocking. Mocks implement repository interfaces (e.g., `MockAuthRepository extends Mock implements AuthRepository`).

## Key Conventions

- **Routing**: All routes must be centralized in `lib/routes.dart`
- **Auth logic**: Must live in bloc/repository layers, never in widgets
- **Branch naming**: `feat/`, `fix/`, `docs/`, `refactor/` prefixes
- **Commits**: Conventional Commits format (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`)
- **Linting**: `avoid_print` is enforced; use proper logging instead

## Firebase Setup

Requires `android/app/google-services.json` (not committed). `firebase_options.dart` is auto-generated by FlutterFire CLI and should not be manually edited. The Firebase project is `parents-data-8c0ee`.
