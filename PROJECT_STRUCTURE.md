# Project structure

K.Note follows the layered layout of the official Flutter architecture guide
([docs.flutter.dev/app-architecture](https://docs.flutter.dev/app-architecture)),
with BLoC/Cubit in the role of the guide's view models. The reasons are recorded
in [ADR 0002](docs/decisions/0002-project-structure.md).

## `lib/`

```text
lib/
├── main.dart                  # Bootstrap: Firebase, AuthRepository, blocs, MaterialApp.router
├── firebase_options.dart      # Generated by FlutterFire CLI, do not edit
├── config/
│   └── assets.dart            # AppAssets: asset paths
├── routing/
│   └── router.dart            # AppRouter: every go_router route and auth redirect
├── domain/
│   └── models/                # Plain data classes, no Flutter/Firebase services
│       ├── document_model.dart  # DataToMap, DocumentModel
│       ├── note.dart            # NoteModel, SavingMode
│       ├── task.dart            # CheckList, TodoItem
│       ├── task_repeat.dart     # TaskRepeat (CheckList.repeat encoding)
│       └── user.dart            # User (from Firebase Auth)
├── data/
│   ├── repositories/
│   │   └── auth_repository.dart # AuthRepository (Firebase Auth, Google Sign-In)
│   └── services/
│       └── firestore_service.dart # FirestoreService: notes, tasks, profile
├── ui/
│   ├── core/                  # Shared by every feature
│   │   ├── app_bloc_observer.dart
│   │   ├── localization/      # strings.dart (Language, LanguageBloc)
│   │   ├── themes/            # styles.dart, style_cubit.dart, dimens.dart
│   │   └── widgets/           # BackgroundUI, ComingSoon, ErrorPage
│   ├── shell/
│   │   └── app_shell.dart     # AppShell: bottom navigation around the tabs
│   ├── auth/
│   │   ├── bloc/              # AuthenticationBloc, LoginCubit, SignUpCubit, form inputs
│   │   └── widgets/           # LoginPage, SignUpPage, forms, login buttons
│   ├── notes/
│   │   └── widgets/           # NotesPage, NoteEditorPage, ArchivedNotesPage, TrashPage, ...
│   ├── tasks/
│   │   └── widgets/           # TasksPage, TaskEditorPage, quick add, pickers
│   └── settings/
│       └── widgets/           # SettingsPage, AboutPage, HelpPage, FeedbackPage, ...
└── utils/
    └── save_in_background.dart  # Fire-and-forget Firestore writes with error reporting
```

### Dependency rules

```text
ui  ──▶  data  ──▶  domain
 │                    ▲
 └────────────────────┘
```

- `domain/` imports nothing from the app. Models only map to and from Firestore
  documents.
- `data/` talks to Firebase and returns `domain` models. It never imports `ui/`.
- `ui/` uses `data/` and `domain/`. Widgets never call Firebase directly; they go
  through a bloc, `AuthRepository` or `FirestoreService`.
- Features do not reuse each other's widgets: what is shared moves to `ui/core/`.
  They may read the session from `AuthenticationBloc` (`ui/auth/bloc/`), and import
  another feature's page only for its `routeName`, to navigate with
  `context.goNamed(TasksPage.routeName)`. Routes themselves are declared in
  `routing/router.dart`.

### Where new code goes

| You are adding | Put it in |
|---|---|
| A screen | `ui/<feature>/widgets/<name>_page.dart`, class `<Name>Page` with a static `routeName`, and its route in `routing/router.dart` |
| State for a screen | `ui/<feature>/bloc/` (`<name>_cubit.dart` / `<name>_bloc.dart`) |
| A widget used by one feature | `ui/<feature>/widgets/` |
| A widget used by several features | `ui/core/widgets/` |
| A Firestore field | the model in `domain/models/`, `FirestoreService`, **and** `firestore.rules` (see `docs/security.md`) |
| Access to a new backend or API | `data/services/` (raw access) or `data/repositories/` (app-facing data) |
| An asset | `assets/` + `pubspec.yaml` + a constant in `config/assets.dart` |

### Conventions

- One public screen per file; file name in snake_case after the class
  (`TasksPage` → `tasks_page.dart`). Screens end in `Page`.
- Imports use `package:knote/...` (no relative imports, no barrel files), sorted
  in groups: `dart:`, packages, then `package:knote`.
- `part` is only used for a bloc's events and states.

## `test/`

`test/` mirrors `lib/`: the tests for `lib/ui/tasks/widgets/task_quick_add.dart`
live in `test/ui/tasks/widgets/task_quick_add_test.dart`.

```text
test/
├── data/                # AuthRepository, FirestoreService (fake_cloud_firestore)
├── domain/models/       # model mapping
├── routing/             # AppRouter configuration
├── ui/                  # blocs (bloc_test) and widget tests
├── utils/
└── firestore_rules/     # Firestore security rules, run in the emulator (Node.js)
```

## Repository root

```text
android/ ios/ web/       # Platform projects (desktop is not configured)
assets/ fonts/           # Images and fonts declared in pubspec.yaml
docs/                    # Setup, architecture, configuration, security, testing, ADRs
firestore.rules          # Firestore security rules, deployed with firebase-tools
firebase.json .firebaserc
```
